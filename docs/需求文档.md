## 1. 项目背景与定位

### 1.1 一句话定位

面向秋招/春招求职者的 AI 模拟面试平台：上传简历和目标 JD，AI 面试官进行多轮模拟面试（定制出题、动态追问），结束后异步生成维度化评估报告。

### 1.2 解决的需求（用户痛点）

1. **真人模拟面试贵且难约**：付费 mock 一场几百到上千元，需预约协调时间；同学互练不专业，问不出追问、给不出有效反馈。
2. **通用题库无法个性化**：网上八股文是通用的，不会针对"你的简历 + 你投的 JD"深挖，而真实面试恰恰顺着简历追问到底。
3. **自己练没有反馈闭环**：对着墙背题，不知道表达是否有结构、是否答到点上、哪里是知识盲区。
4. **心理门槛**：面对真人不敢开口，AI 练习无社交压力、可无限次重来。

### 1.3 项目定位说明（写简历前必读）

- 商业上：赛道已有付费产品验证需求真实性，本项目目标**不是**商业创新。
- 简历上：以 Agent 为业务亮点、以后端工程能力为骨架的展示项目。
- **差异化主打四块**（黑马商城/点评未覆盖，面试主战场）：
  1. SSE 流式长连接 + 并发压测（P95 首 token 延迟）
  2. 自研 Agent 编排层（面试流程状态机、上下文裁剪、追问策略、工具失败兜底）；工具调用循环由 Spring AI + 模型原生 Function Calling 托管
  3. RAG 管线（分块 → embedding → 召回 → 重排 → 引用溯源）
  4. LLM 场景特有的稳定性设计（token 配额限流、模型超时降级、成本控制）

### 1.4 简历项目分工（背景）

| 项目 | 面试里的角色 |
|---|---|
| AI 面试官（本项目，主打放最上） | 原创 + 新技术场景的工程化能力，面试主战场 |
| 黑马商城 | 经典分布式考点：MQ、分布式事务、微服务拆分 |
| 黑马点评 | Redis 深度：缓存三件套、分布式锁 |

## 2. 目标用户与核心场景

**用户**：秋招/春招求职者、跳槽人群。

**核心用户旅程**：

1. 注册登录，上传简历（PDF/Word）+ 粘贴目标 JD
2. 系统解析文档 → 分块 → 向量化入库
3. 发起模拟面试，AI 基于简历/JD/知识库定制出题
4. 多轮对话，AI 根据回答质量动态追问或切换话题（流式输出）
5. 面试结束，异步生成评估报告（技术深度 / 表达结构 / 知识盲区 / 改进建议）

---

## 3. 功能需求

### 3.1 会话与对话管理

- **FR-1** 会话 CRUD：创建/列表/详情，消息持久化 MySQL（会话表、消息表设计是考点）
- **FR-2** 热会话缓存：Redis 缓存进行中会话的上下文，MySQL 落库兜底
- **FR-3** 上下文窗口管理：滑动窗口 + 历史摘要压缩，控制单次请求 token 上限

### 3.2 AI 能力（Agent 编排，核心模块）

- **FR-4** Agent 编排（自研核心）：面试流程状态机——出题/追问/切换话题/结束的流转决策，基于 Spring AI 工具调用能力构建
- **FR-5** Function Calling：工具注册与执行循环由 Spring AI 托管（模型原生调用循环，支持手动接管）；工具粒度设计、超时与失败重试策略自研；首批工具：题库检索、简历要点提取、回答评分
- **FR-6** 动态追问：基于候选人回答质量决定追问深度或切换话题
- **FR-7** 模型接入：基于 Spring AI（OpenAI 兼容协议）接 DeepSeek/Qwen，模型可配置可切换；Spring AI 仅做接入层，决策循环自研（见 6.2 分层边界）

### 3.3 流式交互

- **FR-8** SSE 流式输出：token 级推送到前端
- **FR-9** 断线重连：Last-Event-ID 机制续传

### 3.4 RAG 知识检索

- **FR-10** 文档解析：PDF/Word → 纯文本（Tika/POI），异步任务
- **FR-11** 分块 + embedding + 向量入库（RedisStack 或 pgvector，W4 开发时定）
- **FR-12** 召回 + 重排 + 引用溯源（回答标注来源）

### 3.5 报告与异步任务

- **FR-13** 面试结束触发异步评估报告生成（RocketMQ 削峰）
- **FR-14** 报告维度：技术深度、表达结构、知识盲区、改进建议
- **FR-15** 消费幂等、失败重试、死信队列

### 3.6 稳定性与成本控制

- **FR-16** 令牌桶限流：用户级 QPS + 全局 token 配额（Redis 计数器）
- **FR-17** 熔断降级：LLM 超时/失败 → 重试 → 备用模型/排队提示（Resilience4j）
- **FR-18** 成本记录：按会话统计 token 消耗

### 3.7 用户与门面

- **FR-19** 简单注册登录（JWT）
- **FR-20** 前端：开源 chat UI 套壳，仅保证可演示（重心在后端）

## 4. 非功能需求

- **性能**：SSE 首 token P95 延迟、单机并发长连接数——W7 压测后填实际值，简历 bullet 用真实数据
- **可用性**：LLM 不可用时优雅降级，主链路不雪崩
- **可观测**：Micrometer + Prometheus + Grafana（首 token 延迟、调用成功率、token 消耗）；关键链路日志
- **部署**：Docker Compose 一键启动全部中间件 + 应用
- **安全**：LLM API key 走 .env，不入库不入 git

## 5. 非目标（明确不做）

- 支付、多租户 SaaS

- TTS 语音面试

## 6. 技术方案概要

### 6.1 架构选型

**单体 + 模块化分包**（controller / service / agent / rag / infra）。

为什么不做微服务：黑马商城已承载微服务考点，本项目再拆是重复劳动；核心链路短、单人开发，单体 + 清晰分包更合适，把时间花在流式和稳定性上。面试话术：**两个项目两种选型，证明懂 trade-off，不是为拆而拆。**

### 6.2 技术栈

| 层 | 选型 | 备注 |
|---|---|---|
| 语言/框架 | JDK 17 + Spring Boot 3.x | |
| 存储 | MySQL 8 | 会话/消息/报告 |
| 缓存 | Redis（+ RedisStack 可选） | 会话缓存、限流计数、向量检索候选 |
| 消息 | RocketMQ | 异步报告/文档索引 |
| 流式 | SSE | |
| 稳定性 | Resilience4j | 熔断/重试/降级 |
| 观测 | Micrometer + Prometheus + Grafana | |
| 部署 | Docker Compose | |
| LLM | DeepSeek / Qwen（OpenAI 兼容） | 预算几十元内，本地 Ollama 零成本备选 |
| AI 框架 | Spring AI | 只做接入胶水层：模型接入、流式、工具调用协议、VectorStore 接入 |

**AI 框架分层边界（v1.2 修正）**：
- Spring AI 托管：模型接入、流式推送、工具调用完整循环（模型原生 Function Calling：发起调用 → 执行 → 结果回填 → 继续生成；框架默认托管，另支持手动接管模式）、EmbeddingModel/VectorStore 接口。
- 自研（框架不覆盖的编排层）：面试流程状态机（出题/追问/切换/结束决策）、上下文裁剪与摘要策略、追问策略、工具超时/失败兜底。
- 依据：ReAct 的文本协议模式在原生 Function Calling 时代已过时，手写工具调用循环属于重复造轮子；框架没有也不可能有"模拟面试编排"这种业务逻辑，这才是自研的位置。
- 简历话术：技能栏写"熟悉 Spring AI"，项目亮点写"基于 Spring AI 工具调用能力自研 Agent 编排层（流程状态机 + 上下文策略）"。

### 6.3 与黑马项目的故事线区分（防止面试被问"重复"）

- **MQ**：商城 = 秒杀削峰；本项目 = 报告/索引异步化 + 幂等消费 + 死信队列。业务形态不同，证明理解 MQ 本质而非背场景。
- **Redis**：点评 = 缓存三件套、分布式锁；本项目 = 热会话缓存、token 配额计数器、（可选）向量检索。同一中间件，新场景新用法。

## 7. 里程碑排期

| 周 | 内容 | 验证标准 |
|---|---|---|
| W1 | 表设计、会话 CRUD、Redis 缓存、项目骨架 | 能创建会话并存储消息 |
| W2 | Spring AI 接入与工具调用、面试流程状态机、上下文管理 | Agent 能调用工具完成一次出题 |
| W3 | SSE 流式、上下文裁剪 | 流式对话完整可体验 |
| W4 | RAG 管线 | 回答能引用简历/JD 内容 |
| W5 | RocketMQ 异步报告 + 幂等/死信 | 报告异步生成，消息不丢不重 |
| W6 | 限流、熔断降级、监控埋点 | 超配额被限流、LLM 挂掉能降级 |
| W7 | 压测调优，拿全量数据 | 每条简历 bullet 都有真实数字 |
| W8 | README、架构图、部署线上 demo | 简历上能放可访问链接 |

**时间超期的砍法**（按顺序砍）：多轮摘要压缩 → 向量检索换简化方案 → 保留最小闭环：会话 + SSE + 工具调用 + MQ + 限流。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| LLM API 成本超预算 | DeepSeek 低价模型 + 全局配额限流 + 本地 Ollama 兜底 |
| SSE 压测不达标 | 异步 Servlet/线程模型调优，调优过程本身就是简历素材 |
| RAG 检索效果差 | W4 预留迭代空间：调分块策略、加重排 |
| 总工期超期 | 按第 7 节砍法收缩，保最小闭环 |
