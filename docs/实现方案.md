## 1. 阶段总览

| 阶段 | 周期 | 目标（一句话） | 覆盖需求 | 验证标准 |

| 0 准备 | 1-2 天 | 中间件 + 工程骨架一键起 | 非功能：部署/日志 | compose 一键起全绿，应用健康检查通过 |

## 2. 各阶段细化

### 阶段 0：环境与骨架（1-2 天）

- **Docker Compose**：MySQL 8、Redis（直接用 `redis/redis-stack` 镜像，W4 可能用到 RediSearch，免得换镜像）、RocketMQ（namesrv + broker，注意 broker 的 `brokerIP1` 和内存参数）、Prometheus、Grafana。
- **工程骨架**：JDK 17 + Spring Boot 3.x + Spring AI BOM（BOM 先引入，客户端依赖阶段 2 再加）；按需求文档 6.1 分包 `controller / service / agent / rag / infra / config / common`。
- **日志先行**：第一行代码就上 logback 统一日志 + 滚动策略（控制台 + 文件双通道，按天 + 大小滚动，14 天留存）。
- **配置**：`.env` 存所有环境变量（MySQL 密码、JWT 密钥、LLM API key），docker compose `env_file` 与 Spring `spring.config.import` 双通道读取；`.gitignore` 先于第一次 commit 排除 `.env`。
- **验证**：compose 一键起，`/actuator/health` UP，log 文件正常滚动。

### 阶段 1：会话域（W1）

- **表设计（考点）**：一次建好初版 `user / interview_session / interview_message / interview_report(预留) / resume_file(预留)`，走 Flyway 版本化管理：
  - `interview_message` 建 `uk_session_seq(session_id, seq)` 唯一键，`seq` 为会话内递增序号，兼作 W3 SSE 的 Last-Event-ID 偏移量；
  - `interview_session` 建 `idx_user_updated(user_id, updated_at)`，会话列表按最近活跃排序；
  - 用户/会话逻辑删除，消息物理保留（评估报告依赖完整对话记录）。
- **FR-19 轻量 JWT**：注册/登录 + HandlerInterceptor 拦截，JWT 用 jjwt，密码 BCrypt（spring-security-crypto 单包，不引入完整 Spring Security）。
- **FR-2 缓存策略（考点）**：进行中会话的最近 50 条消息存 Redis List（`session:ctx:{id}`），写路径 = MySQL 事务提交后再写 Redis（Cache-Aside，防回滚脏缓存）；读路径 = Redis 优先，未命中读库回填，**任何 Redis 异常 catch 住降级读库**，主链路不受影响。TTL 24h 滚动续期。
- **验证**：curl 走通注册→建会话→发消息→列表/详情；**Redis 不可用时接口仍返回正确数据 + 日志出现降级警告**。

### 阶段 2：Agent 编排核心（W2，全项目最重的一周）

- **FR-7 接入层**：Spring AI `ChatClient` + OpenAI 兼容协议指向 DeepSeek/Qwen，多模型配置化，做简单模型路由（主模型 + 预留备用模型位，阶段 6 降级直接用）。
- **FR-5 工具**：三个首批工具（题库检索、简历要点提取、回答评分）用 Spring AI `@Tool` 注册。**关键：先写 stub 实现，只定接口契约**——阶段 4 用真 RAG 替换题库检索/简历提取，接口不动。
- **FR-4 状态机（自研决策层）**：状态 `OPENING → QUESTIONING → PROBING → SWITCHING → CLOSING → DONE`。决策方式：LLM 结构化输出（JSON：下一状态 + 行动 + 追问深度），状态机代码做守卫和非法流转拦截——决策是智能的，流转是可控的。
- **FR-6 动态追问**：挂在 PROBING 决策上，输入 = 回答评分结果 + 当前状态，决定追问深度或切换话题。
- **FR-3 基础版**：滑动窗口 + 字符数近似 token 估算，摘要压缩留到砍法第一条的位置。
- **顺手埋点**：从响应 usage 取 token 数写进 `interview_message.token_count`，FR-18 数据从现在开始积累。
- **验证**：单测/命令行走一轮"出题→候选人回答→调评分工具→决策追问→下一题"；日志可见完整 工具调用→结果回填→继续生成 链路。

### 阶段 3：SSE 流式（W3）

- **FR-8**：Servlet 栈 `SseEmitter` + 专用异步线程池（独立 executor、显式超时）；周期心跳 comment 事件防代理断连。不上 WebFlux——与压测故事（异步 Servlet/线程模型调优）一致。
- **事件协议自定**：`delta`（token 增量，id = 消息 seq）、`done`、`error`。id 用 seq，FR-9 续传 = 按 seq 从 Redis/MySQL 回放 + 续流。
- **FR-3 收尾**：单次请求 token 上限裁剪完整生效。
- **FR-20 前端**：开源 chat UI 套壳，只要求能连 SSE、能重连。
- **验证**：浏览器打字机效果完整走一轮对话；杀掉网络 30 秒重连，内容不丢不重。

### 阶段 4：RAG 管线（W4）

- **FR-10**：Tika 统一解析 PDF/Word，异步任务先用 `@Async` 线程池实现（不上 MQ，W5 引入 MQ 后把文档索引任务迁过去，正好是一次真实迁移）。
- **FR-11 分块**：结构感知分块——按标题/段落递归切，500-800 token、overlap 10-15%；简历按 section 切。
- **两个"W4 开发时定"的决策点，先给推荐**：
  - **向量库：推荐 RedisStack**。单体项目已有 Redis 运维、数据量千级 chunk、Spring AI 有现成 `RedisVectorStore`；pgvector 备选。
  - **Embedding：DeepSeek 没有 embedding API**，推荐 SiliconFlow/Qwen embedding（便宜）或本地 Ollama `bge-m3`（零成本，兼降级兜底）。走 Spring AI `EmbeddingModel` 接口，实现可换。
- **FR-12**：召回 top-K → 重排（bge-reranker API 或 LLM 打分）→ 引用溯源（chunk 元数据带 source/section/offset，回答生成后挂引用标记）。
- **验证**：上传简历后问"我简历里 XX 项目是怎么做的"，回答引用简历原文并标注来源；替换阶段 2 的 stub 工具后回归出题链路。

### 阶段 5：MQ 异步报告（W5）

- **链路**：面试结束 → 发 RocketMQ 消息 → 消费者聚合会话消息 → LLM 生成四维报告 → 落库 + 状态更新。
- **FR-15 三个都真实现**：幂等（报告表 `uk_session` 唯一键 + Redis setnx 双保险）、重试（消费失败退避重试 N 次）、死信（进 DLQ + 补偿查询）。与黑马商城"秒杀削峰"故事区分——幂等和死信就是这个项目的 MQ 深度。
- **文档索引任务迁入 MQ**（阶段 4 遗留）。
- **验证**：重复投递不重复生成；必失败消息走到死信；停 consumer 再恢复，消息不丢。

### 阶段 6：稳定性与成本（W6）

- **FR-16**：用户级 QPS 令牌桶（Redis + Lua 原子脚本）；全局 token 配额 = Redis 按日计数器，超限拒绝并提示。做在 LLM 调用统一入口。
- **FR-17**：Resilience4j `TimeLimiter + Retry + CircuitBreaker` 包住 LLM 调用，降级链 = 重试 → 切备用模型 → 排队提示。验证方式：拔 API key。
- **FR-18**：按会话聚合 token 消耗报表接口（数据阶段 2 起积累）。
- **可观测**：Micrometer 自定义指标（首 token 延迟 Timer、LLM 调用成功率、token 消耗 Counter），Grafana 三块面板。
- **验证**：压限流触发拒绝；拔 key 主链路降级不雪崩；Grafana 有数据。

### 阶段 7：压测调优（W7）

- 工具推荐 **k6**（SSE 支持好），场景：并发长连接数、首 token P95、错误率。
- 调优方向按预期收益排：Tomcat 异步线程池参数 → SseEmitter 超时与心跳频率 → Redis/MySQL 连接池 → LLM 客户端连接复用。
- 产出：压测报告（场景、调优前后对比数据），每条 bullet 一个数。

### 阶段 8：交付（W8）

- README（架构图、选型 why-not 自检表）、compose 一键部署、云服务器上线 demo，跑通验收标准 1-4。

## 3. 跨阶段要点

1. **工具接口先行**（阶段 2 定契约、阶段 4 换实现）——整个排期最重要的解耦，RAG 晚三周但不返工。
2. **消息 seq 贯穿三个功能**——持久化序号同时服务 FR-9 断线续传和上下文窗口裁剪，阶段 1 建表已定。
3. **砍法与阶段对应**（需求文档第 7 节）：砍多轮摘要压缩 = 阶段 2 尾部；砍向量检索 = 阶段 4 换关键词检索；最小闭环 = 阶段 1 + 3 + 2(工具调用) + 5 + 6(限流)。进 W5 前评估一次进度，决定是否触发砍法。

## 4. 假设清单（细节级，可纠正）

1. ORM 用 MyBatis-Plus（国内面试主流）。
2. SSE 走 Servlet `SseEmitter` 而非 WebFlux（与需求文档"异步 Servlet 调优"一致）。
3. Spring AI 用 1.0.x GA。
4. 向量库倾向 RedisStack，正式决策留到 W4。
5. 前端套壳选型到阶段 3 再定，不影响后端。
